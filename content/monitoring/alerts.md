## 먼저 이것만

경보는 **판단**, SNS·Lambda·Discord는 **전달**을 맡는다. 화면의 오류율이 아니라 **5xx 건수**가 경보 기준이다.

총총의 dev·prod 경보는 `/actuator/*`를 제외한 5xx가 **한 수집 구간에 1건 이상**이면 평가 대상이 된다. 평가 간격 1분, 보류 0초, 복구 2분이다. 이는 알림이 정확히 1분 안에 온다는 보장은 아니다.

## 전달 과정

두 환경의 경보가 SNS 주제 **chongchong-alerts**로 보낸다. SNS의 구독 대상은 Lambda **chongchong-alarm-to-discord**다. Lambda가 경보 이름·상태·사유·시각을 Discord 웹훅으로 POST한다.

제공된 Lambda 코드에서는 이름이 `chongchong-prod-`로 시작하고 상태가 `ALARM`일 때만 지정 역할을 멘션한다. dev도 메시지는 보내지만 이 조건의 역할 멘션은 없다.

## 직접 확인

CloudWatch 경보의 **기록**에서 실제 ALARM 전이를 보고, **작업**에서 SNS 연결을 확인한다. SNS 구독 다음에는 Lambda 실행 로그를 본다. 웹훅 환경 변수 누락, 8초 연결 시간 초과, 실패 HTTP 응답은 Lambda에서 오류가 된다.

Discord 테스트 메시지 도착은 확인했다. **실제 5xx부터 자동 전달까지 이어진 기록은 아직 확인되지 않았다.** 운영 서버에 의도적으로 오류를 만들지 말고 dev에서 안전한 시나리오로 확인한다. 웹훅 URL·토큰은 공유하지 않는다.
