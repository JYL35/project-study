## 먼저 이것만

**로그**는 요청 한 건의 일기다. **메트릭**은 여러 요청을 숫자로 요약한 성적표다. **알림**은 문제가 생겼을 때 사람에게 알려 주는 호출이다.

사용자가 “오류가 났어요”라고 하면 메트릭으로 **언제, 얼마나** 실패했는지 보고, 그 시간대의 로그로 **어떤 요청에서 왜** 실패했는지 찾는다.

## 총총에서는

- 피즈: 요청·오류를 JSON으로 남기고 **Docker awslogs → CloudWatch Logs**로 보낸다.
- 이든: 요청 수·상태·응답 시간을 **Actuator → ADOT → CloudWatch OTel 메트릭**으로 연결했다.
- 바니: CloudWatch 대시보드와 **5xx 경보 → SNS → Lambda → Discord**를 구성했다.

대시보드는 메트릭을 보는 화면이다. 대시보드가 보인다는 사실만으로 알림 전달까지 성공했다고 볼 수는 없다.

## 직접 확인

위 실습에서 **요청 보내기**를 누르고 같은 요청이 로그·메트릭으로 어떻게 나뉘는지 따라가 보자. 수집기를 중지한 상황에서는 어느 경로가 계속 살아 있는지 확인한다.

이 사이트의 실습 데이터는 모두 **모의 데이터**다. 실제 AWS나 총총 서버를 호출하지 않는다.
