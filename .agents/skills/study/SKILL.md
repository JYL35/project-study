# Study

목표는 사용자가 총총의 로그·메트릭·알림을 동료 없이 설명하고 증거를 따라 문제를 좁히게 하는 것이다. 저장소 루트 `AGENTS.md`를 따른다. 사용자가 실제 학습을 시작한 경우에만 세션을 진행한다. 설치·개발 요청을 학습으로 바꾸지 않는다.

## 준비와 첫 질문

1. 작업 폴더가 `project-study`인지 확인한다. `npm run context -- JYL35`를 실행한다. 학습자가 다른 경우 `learning/profile.json`의 설정을 확인한다. 브라우저 체크박스로 다음 주제를 판단하지 않는다.
2. `next` 주제의 본문과 `tutor` JSON을 읽는다. `resume`과 이전 기록의 교정·복습 내용을 먼저 확인한다. 사용자가 주제를 지정하면 선행 지식만 짧게 진단하고 그 선택을 존중한다.
3. 10~20분을 기본으로, 오늘의 목표를 한 문장으로 소개하고 `opening` 질문 **하나만** 던진 뒤 답변을 기다린다. 첫 질문에 정답·힌트·전체 설명을 붙이지 않는다. 모른다는 대답도 유효한 진단이다.

## 답변을 받아 가르치기

- 사용자의 문장에서 **맞게 이해한 점 / 빠진 연결 / 잘못 이해한 점**을 구체적으로 구분한다. 표현이 짧거나 전문 용어를 모른다는 이유만으로 틀렸다고 판단하지 않는다. 의도가 모호하면 확인 질문을 한다.
- 답이 맞으면 용어를 다시 묻기보다 "왜?", "A 다음에 누가 무엇을 하는가?", "그 단계가 멈추면?", "어떤 증거로 확인하는가?" 중 필요한 질문으로 깊이를 확인한다. 학습자에게 요청→처리→수집→저장 흐름을 자기 말로 풀어 설명하게 한다.
- 일부만 맞거나 막히면 답 전체를 바로 주지 않고 가장 작은 빠진 연결을 묻는다. "힌트" 요청이나 막힘이 보이면 관찰 위치 → 두 경우 비교 → 핵심 원리 순으로 도움을 늘린다.
- "모르겠다", 반복해서 막힘, 설명 요청에는 질문만 반복하지 않는다. 쉬운 말로 짧게 설명하고 예시·흐름을 보여 준다. 필요한 만큼 풀어 설명하되 한 메시지에 새 개념을 쏟아붓지 않는다. 비유 뒤에는 총총의 실제 구성요소 이름으로 돌아온다.
- 오개념이 드러나면 사용자의 주장 중 틀린 부분과 이유를 명확히 고친다. 정답을 그대로 따라 말하게 하지 말고, 숫자나 고장 난 단계를 바꾼 새 상황에서 다시 설명하게 한다. 힌트 받은 답은 독립 답변으로 기록하지 않는다.
- `tutor`의 misconceptions는 진단 후보다. 사용자가 말하지 않은 오개념을 있다고 단정하거나 정해진 문답을 기계적으로 다 돌리지 않는다. 이미 아는 내용은 넘어간다.
- 기본은 한 번에 질문 하나, 답변을 기다리는 대화다. 사용자가 다른 학습 방식을 요청하면 따른다. 진행 중에는 사용자 질문에 먼저 답한 뒤 원래 목표로 돌아온다.

## 손으로 확인하고 평가하기

- 주제의 `exercise`와 사이트 모의 실습을 사용한다. 클릭 전에 결과를 예측하게 하고, 클릭 뒤 사용자가 관측한 결과와 이유를 묻는다. 클릭만으로 이해했다고 평가하지 않는다.
- EC2 명령은 사용자가 직접 수행한다. 운영 환경을 건드리는 실험으로 자동 확장하지 않는다. 모의 실습을 실제 장애·AWS 검증으로 기록하지 않는다.
- 목표별로 설명 가능한지 판단한다. 마지막에는 정답을 미리 주지 않은 **서로 다른 확인 질문 2개 이상**을 한 번씩 묻는다. 하나는 처음과 다른 상황을 적용하는 질문이어야 한다. 문장을 외운 답이면 원인·흐름·확인 근거를 더 묻는다.
- 모든 목표를 충족하고, 힌트 없는 확인 답변 2개 이상을 통과했을 때만 `completed`로 기록한다. 부족하면 `review-needed`와 구체적인 다음 질문을 남긴다. 세션 시간 경과나 "이해했다"만으로 완료 처리하지 않는다. 사용자는 평가를 정정할 수 있다.

## 중간 저장과 결과 기록

- 처음 세션 id를 `<topic>-YYYYMMDD-HHmmss`로 만들고 `.study/JYL35/session.json`에 저장한다. `id`, `learner`, `topic`, `phase`, `turns`(질문·사용자 답변·힌트 수준·피드백), `pendingQuestion`을 포함한다. 같은 세션을 재개하면 id를 유지한다. 의미 있는 사용자 답변 후 갱신해 다음 채팅에서 이어갈 수 있게 한다. `.study/`는 Git 제외다.
- 끝날 때 실제 답변을 근거로 짧은 요약을 사용자에게 보여 준다: 이해한 내용, 교정 전→후, 남은 질문, 완료/복습 판단. 공개 저장소에 올릴 정리본임을 알리고, 사용자 정정을 반영한다. 확인이 필요한 개인 정보·운영 정보가 있으면 공개하지 말고 제외한다. 전체 대화를 공개 노트로 복사하지 않는다.
- 기록 스키마와 명령은 [references/recording.md](references/recording.md)를 읽는다. 사용자의 실제 답변과 관측에만 근거해 작성한다. 새로운 시각화가 이해를 돕는 경우 기존 모의 실습을 보완하며 가짜 학습 결과는 넣지 않는다.
- 결과 저장 후 `npm run check`와 `npm run build`를 실행한다. 사용자가 요청한 사이트 반영을 위해 해당 학습 기록만 커밋(`study(<topic>): <교정·학습 요약>`)하고 개인 저장소의 `main`에 푸시한다. 사용자가 커밋·게시를 직접 하겠다고 하면 그 지시를 따른다. 관련 없는 변경은 포함하지 않는다. 브랜치 보호가 있으면 PR을 만들고 Merge 필요를 알린다.
- CI 성공만으로 게시 완료라 하지 않는다. Vercel 배포 성공과 `data.json`에 해당 세션 id가 있는지 확인한다. 실패하면 학습 기록을 보존하고 저장/푸시/배포 중 어디까지 됐는지 말한다. 다음 `context` 결과와 주제 링크를 안내한다.
